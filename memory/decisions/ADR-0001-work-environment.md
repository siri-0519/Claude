# ADR-0001 · 작업 환경의 네 가지 보장을 훅으로 강제한다

- 상태: accepted
- 일자: 2026-09-04

## 맥락

사용자가 요구한 네 가지: (1) 규칙 준수 (2) 세션 간 문맥 유지 (3) 토큰 효율
(4) 파생 데이터 연계. 넷 다 "CLAUDE.md에 적어두기"로는 만족되지 않는다. 모델은
긴 컨텍스트에서 지시를 흘리고, 세션은 기억을 잃고, 파생 관계는 사람 머릿속에만 남는다.

## 결정

**검사 가능한 것은 전부 훅으로 옮기고, 검사 불가능한 것만 자연어로 남긴다.**

1. 규칙을 두 층으로 나눈다.
   - hard: `ops/rules/hard.yml`이 단일 진실원. PreToolUse/PostToolUse/Stop 훅이
     읽어서 집행한다. CLAUDE.md의 규칙 표는 이 파일에서 **생성**되므로 둘이 어긋날 수 없다.
   - soft: `ops/rules/soft.md`. 말투처럼 수치화 불가능한 것. 강제가 불가능하므로
     짧게 유지하고 UserPromptSubmit 훅으로 매 턴 프롬프트 직전에 재주입한다.
     이것은 준수를 보장하지 않는다 — 확률을 올릴 뿐이다.

2. 문맥은 계층화한다. `memory/STATE.md`(4KB 상한)만 자동 주입하고, 나머지는
   `ops ctx log --grep`으로 필요할 때만 당겨 읽는다. 로그의 정본은 jsonl 하나이고
   사람용 한국어 다이제스트는 거기서 생성된다 — 두 벌을 따로 쓰면 반드시 어긋난다.

3. 토큰은 "지도 먼저" 원칙. `INDEX.md`가 모든 아티팩트의 id·라벨·요약을 담으므로
   파일을 열지 않고 후보를 좁힐 수 있다.

4. 파생은 **해시 고정**으로 표현한다. B의 front-matter가 A의 id와 파생 시점 본문
   해시를 함께 담는다. A의 본문이 바뀌면 해시가 어긋나고 B는 stale이 된다.
   해시는 front-matter를 제외한 본문에서만 계산하므로, A의 라벨 수정 같은
   메타데이터 변경은 B를 건드리지 않는다.

## 대안과 기각 사유

- **CLAUDE.md에 규칙만 나열**: 강제력 0. 긴 세션에서 반드시 흘린다.
- **모든 규칙을 하드 차단**: 말투 같은 규칙은 판정 자체가 불가능하다. 억지로
  정규식을 만들면 오탐이 준수보다 비싸진다.
- **파생 관계를 별도 DB/YAML에 관리**: 파일과 관계가 분리되면 파일을 옮기거나
  지울 때 반드시 어긋난다. front-matter에 동봉하면 파일과 함께 움직인다.
- **B를 A에서 자동 재생성**: 지식 문서는 결정론적 함수가 아니다. 자동 갱신 대신
  **stale 표시 + 종료 차단**으로 사람/모델의 판단을 강제하는 쪽을 택했다.

## 결과

- 좋은 점: 규칙 위반이 조언이 아니라 차단이 된다. 파생 누락이 턴 종료를 막는다.
- 비용: 매 턴 소프트 규칙 재주입에 약 150 토큰. 훅당 python 프로세스 1회.
- 마찰: 규칙 패턴을 본문에 담는 파일(테스트·규칙 문서)은 예외 경로가 필요했다.
  `content_scan_exempt`로 좁게 열어두었다.
- 탈출구: 일회성 `OPS_ALLOW=<규칙id>` — 단 `escape:`를 선언한 규칙에만 듣는다
  (지금은 HR-001·HR-002). 나머지는 우회로가 없고, 원인을 고치거나 규칙을 고쳐야 한다.
  그 밖에 디버깅용 `OPS_HOOKS=off`, Stop 차단 3회 상한.
  마지막 것이 없으면 고칠 수 없는 위반에 세션이 갇힌다.
