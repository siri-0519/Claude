# 훅 글 — 훅이 넣거나 되돌리는 글마다 무엇을 하게 하려는 글인가

검토용 문서다. 훅은 이 파일을 읽지 않고, 목차와 STATUS 에도 오르지 않는다 (`.ops.yml` 제외 목록). 훅 글을 고칠 때만 연다.

기준은 하나다. **그 글만 받은 에이전트가 「목적」 칸의 행동을 하면 통과다.** 검증은 맥락 없는 에이전트 셋(haiku · sonnet · opus)에게 글만 주고 "이 글을 받으면 바로 다음에 무엇을 하겠나"를 한 문장으로 받아 목적과 견준다. 판정 칸은 그 결과다.

검증 기록 (2026-09-14). 1판은 처음 글 35개를 haiku · sonnet · opus 셋이 읽었다(sonnet 의 답은 34분 뒤에 왔다). 행동이 목적과 어긋난 것은 haiku 의 B7(수정이 아니라 답을 다시 쓴다로 읽음), haiku 와 sonnet 의 A4(개수만 보고 그대로 답한다), sonnet 의 A16(대신 무엇을 하는지 모름) 셋이고, 모호하다고 짚은 것이 열넷이었다 — 어느 원본을 고치나(A6 · A7), 어느 표시를 붙이나(A8 · A15), [제안]→[확인]은 되돌리나(A15), 대신 무엇을 하나(A10 · A16), 어떻게 줄이나(A11), 규칙 전문이 없다(A13), 「사이드카」 · 「생성 블록」 · 「조상」 · 「자취」 같은 말(A3 · A6 · A7 · A16 · A17), 보기 날짜가 고정돼 있다(B4), 마지막 줄이 두 갈래로 읽힌다(B5). 틀의 글 열일곱과 me · broadcast 의 B4 · B5 · B7 을 고쳐 썼다. 2판은 고친 글 스무 개를 haiku · sonnet · opus 셋이 읽었고 행동은 셋 다 스무 개 전부 목적과 같았다. sonnet 은 「레포 시험」(시험 레포의 이름) · 「자취」 · 「[훅 stop]」 · B5 의 「그 이름」이 어느 쪽인지를 짚었고, 앞 셋은 3판 글에 넣었다. opus 가 남긴 모호함(오늘이 며칠인지, 방금 고친 파일이 어느 쪽인지, 규칙 전문, 사용자에게 알리나, 요약으로 접혔다는 비유)을 3판 글에 넣었다. 3판 글은 아직 에이전트가 읽지 않았다.

항목 읽는 법. 번호는 레포-순번이다. 자리는 세션시작 · 물음직전 · 저장직전 · 명령직전 · 도구직후 · 답끝 · 커밋직전 · push직전 가운데 하나다. 글은 훅이 보내는 글 그대로고 변수 자리는 `<…>`다. 목적은 그 글을 받은 에이전트가 해야 하는 행동 한 문장이다. 근거는 목적이 어디서 왔나다.

이 판에 넣지 않은 것. `ops/rules/판단.md`의 판단 규칙 여섯(`설계.md` 부록 C에서 따로 검증했다). me · broadcast 의 `rules.md` 규칙 문장(`설계-부록.md` 부록 A에 행선지가 있고, 2 · 3단계에서 판단 규칙과 기계 규칙으로 바뀐다 — 본인이 짚은 낱말만 고쳤다). creation 의 `tools/check-*.py` 가 커밋 직전에 내는 검사 문장(4단계에서 본다).

## A. 틀 (이 레포 · `ops/lib/훅.py` `기계.py` `판정.py` `어긋남.py`)

### A1 · 세션시작 · 레포 상태와 어긋남 목록
- 글: `레포 <이름>: 브랜치 <b> / 마지막 커밋 <h> (메시지 첫 줄: <제목>) / 커밋 안 한 변경 <N>개 — 지난 세션이 남긴 것이어도 git status 로 보고 첫 답 안에 커밋한다 / 이 브랜치는 아직 원격에 없다 — git push -u origin <b>` — `고친 것은 이 세션의 브랜치로 커밋하고 push 한다. 기본 브랜치는 <main> 다. 답이 끝날 때 훅이 커밋 · push 를 확인한다.` — `아래 어긋남 목록의 줄은 사용자의 요청과 상관없어도 이번 세션의 첫 답 안에서 처리하고, 처리한 것을 답에 한 줄로 알린다.` 이어서 어긋남 목록 전체, 또는 `어긋남 목록(memory/어긋남.md)은 비어 있다.`
- 목적: 에이전트가 지금 브랜치와 커밋 상태를 알고, 답이 끝나기 전에 커밋 · push 해야 한다는 것을 알고, 어긋남 목록의 항을 이번 세션에서 다룬다.
- 근거: `설계.md` 2절(세션 시작에 들어가는 것은 목차와 어긋남 목록) · 4절.
- 판정: 1판 모호 → 고쳐 씀 → 2판 haiku · sonnet · opus 일치 → 3판 글(위)은 미검증

### A2 · 세션시작 (요약 · 재개 뒤) · 다시 읽기
- 글: `대화가 요약으로 바뀌었다. 요약 앞에서 읽은 파일은 문맥에 없다. 이번 물음에 걸리는 주제 파일(CLAUDE.md 「언제 무엇을 읽나」 표에서 물음의 말이 든 행의 파일)을 답하기 전에 다시 읽는다. 「고칠 때」 규칙도 다음 저장 때 다시 들어온다.`
- 목적: 요약 앞에서 읽은 파일을 읽은 것으로 치지 않고, 답하기 전에 주제 파일을 다시 읽는다.
- 근거: me · broadcast 의 session-start-context.sh 가 같은 자리에서 하던 말. 요약 뒤에 안 읽고 고쳐 어긋난 줄이 생긴 사고(2026-09-07 read-before-edit.py 「왜 있나」).
- 판정: 1판 모호 → 고쳐 씀 → 2판 haiku · sonnet · opus 일치 → 3판 글(위)은 미검증

### A3 · 어긋남 목록의 머리와 항
- 글: 머리: `원본이 바뀌어 낡은 것이 여기 오른다. 파생물은 다른 파일(출처)을 읽고 다시 쓴 파일이고, <파생물> ← <출처> 는 출처가 바뀐 뒤 파생물이 아직 따라오지 않았다는 뜻이다. 어긋난 날은 출처가 바뀐 날이다.` `이 목록은 막지 않는다. 항마다 이번 세션에 이렇게 한다. 파생물을 출처의 바뀐 절에 맞춰 고치고 ops ack <파생물> 을 돌린다. 고칠 것이 없으면 ops ack <파생물> --그대로 "<이유>" 를 돌린다. 둘 다 항을 지운다.` `스크립트가 세션 시작마다 다시 만들고 커밋하지 않는다.` 절마다 한 줄 — 브랜치: `합칠지는 사용자가 정한다. 사용자가 합치라고 하면 git merge <브랜치> 로 합치고 push 한다.` 폐기 번호: `폐기된 결정을 아직 가리키는 줄이다. 그 줄을 지금 맞는 문장으로 고치거나 지운다.` 생성 파일: `ops build 를 돌리면 맞는다.` 항은 `- <파생물> ← <출처> · 어긋난 날 <날짜> · 바뀐 절: <절들>`
- 목적: 항마다 파생물을 출처의 바뀐 절에 맞춰 고치고 ack 하거나, 고칠 것이 없으면 이유를 대고 ack 한다. 안 합쳐진 브랜치는 합칠지 본다. 막히지 않으므로 답을 끝내는 데는 지장이 없다는 것을 안다.
- 근거: `설계.md` 4절.
- 판정: 1판 모호 → 고쳐 씀 → 2판 haiku · sonnet · opus 일치 → 3판 글(위)은 미검증

### A4 · 물음직전 · 개수 한 줄
- 글: `어긋남 목록(memory/어긋남.md)에 <N>줄, 이번 세션에 새로 오른 것 <M>줄: <이름들> — 새로 오른 줄은 이번 답에서 고치거나 ops ack 한다.` 새것이 없으면 `… 이번 세션에 새로 오른 것 없음`

### A5 · 도구직후 · 새로 오른 항
- 글: `방금 고친 것(<파일>) 때문에 어긋남 목록에 새로 올랐다 (막지 않는다):` 이어서 항 줄들 · `이 답이 끝나기 전에 파생물을 출처의 바뀐 절에 맞춰 고치고 ops ack <파생물> 을 돌리거나, 고칠 것이 없으면 ops ack <파생물> --그대로 "<이유>" (파생물을 고치지 않고 둔다는 뜻) 를 돌린다. 브랜치 · 폐기된 번호 · 생성 파일 줄은 memory/어긋남.md 의 그 절에 적힌 대로 한다.`

- 근거: `설계.md` 4절. 옛 기계의 HR-008(출처를 고치면 파생물이 낡는다) 알림.

### A6 · 저장직전 (막기) · 생성 파일
- 글: 파일마다 다르다. `STATUS.md 는 스크립트가 주제 파일마다의 「지금」 절에서 만든다. 손으로 고치지 않는다. 바꾸려는 줄이 든 주제 파일의 「지금」 절을 고치고 ops build 를 돌린다.` / `README.md 는 스크립트가 .ops.yml 의 소개 칸과 주제 파일마다의 「지금」 절 첫 줄에서 만든다. …` / `worklog.md 는 스크립트가 git log 에서 만든다. 손으로 고치지 않고 커밋하지 않는다. 적을 것은 커밋 메시지 첫 줄에 적는다.` / `memory/어긋남.md 는 스크립트가 파생물 옆 파일(<파생물>.meta.yml)과 출처 파일에서 만든다. 손으로 고치지 않는다. 항을 지우려면 파생물을 고치고 ops ack <파생물> 을 돌린다.`
- 목적: 그 파일을 고치지 않고, 그 내용이 나오는 원본을 고친 뒤 `ops build` 를 돌린다.
- 근거: `설계.md` 4절 첫째 종류의 파생물.
- 판정: 1판 모호 → 고쳐 씀 → 2판 haiku · sonnet · opus 일치 → 3판 글(위)은 미검증

### A7 · 저장직전 (막기) · 생성 블록
- 글: `CLAUDE.md 의 「<이름>」 블록(<!-- BEGIN GENERATED: <이름> --> 와 <!-- END GENERATED: <이름> --> 사이)은 스크립트가 만든다. 표의 첫째 · 둘째 칸은 .ops.yml 의 목차 항목(말 · 파일)에서, 셋째 칸은 그 주제 파일의 「지금」 절 첫 줄에서 온다. 그 사이는 손으로 고치지 않고, 같은 내용을 블록 밖에 적지도 않는다. 블록 밖의 다른 글은 고쳐도 된다. 바꾸려는 것이 첫째 · 둘째 칸이면 .ops.yml 의 그 항목을, 셋째 칸이면 그 주제 파일의 「지금」 절 첫 줄을 고치고 ops build 를 돌린다.`

- 근거: 같음.
- 판정: 1판 모호 → 고쳐 씀 → 2판 haiku · sonnet · opus 일치 → 3판 글(위)은 미검증

### A10 · 명령직전 (막기) · 셸 검사
- 글: `이력을 다시 쓰거나 원격 브랜치를 지우는 push(--force · --delete · :브랜치)다. 하지 않는다. 원격과 다르면 먼저 git pull --no-rebase 로 합친 뒤 보통 push 를 한다. 원격 브랜치를 지우는 것은 사람이 GitHub 에서 한다. 사용자에게 그렇게 알린다` / `이력을 다시 쓰는 명령(filter-branch · filter-repo)이다. 하지 않는다. 이미 있는 커밋은 그대로 두고 새 커밋으로 고친다` / `기계(<자리> — ops/ · .claude/ · memory/ · .ops.yml 이 기계다)를 통째로 지우는 명령이다. 하지 않는다. 지울 파일이 있으면 이름을 하나씩 대고 git rm <파일> 로 지운다` / 생성 파일로의 재지정이면 A6 의 그 파일 설명 + `셸로 덮어쓰지 않는다.`
